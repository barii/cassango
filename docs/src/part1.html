Part I

User guide

Everything you need to run cassango and use it from the shell, from Rust and over HTTP. You don't need to know how it works inside. Part II covers that.

1. What is cassango?

cassango is a small distributed database that stores JSON documents. It spreads and copies data across a cluster the way Apache Cassandra does. You query documents the way you query MongoDB.

From CassandraFrom MongoDB
Gossip membership and failure detection, seed nodesSchemaless JSON documents with an _id
Consistent-hash token ring with virtual nodes; no master, any node coordinatesFilters: $eq $ne $gt $gte $lt $lte $in $nin $exists $size $not $and $or $nor, dotted paths, array matching
Replication factor and tunable consistency: one / quorum / allSort, skip, limit
Last-write-wins timestamps, tombstones, gc_graceUpdate operators $set $unset $inc $push
Hinted handoff, read repair, Merkle-tree anti-entropy repairSecondary indexes: equality, $in, ranges, arrays
Node lifecycle: bootstrap, decommission, removenode, cleanupA mongo-style shell: db.users.find({age: {$gt: 30}})
LSM storage: commit log → memtable → SSTables, bloom filters, compactionAn async Rust driver with typed collections

You talk to cassango in one of three ways, all over HTTP with JSON bodies. Any node can take any request. The node you contact coordinates it, sending work to the nodes that hold the data.

Words used in this guide

TermMeaning
DocumentA JSON object. Its _id (a string) is the key. If you leave it out, a UUID is generated.
CollectionA named group of documents, like a MongoDB collection or a Cassandra table. It's created by the first write. Names use [A-Za-z0-9_-].
NodeOne running cassango server process.
Replication factor (RF)How many nodes store each document. The default is 3.
ReplicaA node that stores a given document.
CoordinatorThe node that received your request. It forwards work to the replicas and collects the answers.
Consistency levelHow many replicas must answer before a read or write succeeds: one, quorum (a majority) or all.
TombstoneThe marker a delete writes. It's copied like a normal write and purged after --gc-grace-secs.

3. Replication and consistency

Every document is stored on RF nodes (3 by default). For every request you choose how many of those replicas must answer. With RF 3, quorum means 2. The default is quorum.

  • Write at quorum and read at quorum and a read always sees the latest acknowledged write, because any two majorities overlap.
  • If too few replicas are alive, the request fails at once with 503 unavailable and nothing is written.
  • If enough replicas are alive but don't answer in time, you get 504. The write may have reached some replicas.
  • Writes for a replica that is down are queued on the coordinator (a hint) and delivered when it comes back.
  • Concurrent writes to one document are resolved by last write wins, using the timestamp the coordinator assigns.

4. The shell: cassango-cli

cassango-cli                                           # interactive shell (history: ~/.cassango_history)
cassango-cli -e 'db.users.count()'                     # run one statement and exit
cassango-cli -e 'db.a.insert({x: 1})' -e 'db.a.count()' # several statements
cassango-cli -f examples/tour.cassango                 # run a script file
echo 'db.users.find({city: "York"})' | cassango-cli    # statements from stdin
cassango-cli -H 10.0.0.5:7001,10.0.0.6:7001            # use the second host if the first is down
CASSANGO_HOST=10.0.0.5:7001 cassango-cli               # host from the environment
FlagMeaning
-H, --host <list>Nodes to talk to, comma-separated. Later ones are used if earlier ones are unreachable. Default 127.0.0.1:7001 or $CASSANGO_HOST.
-e, --execute <stmt>Run a statement and exit. Repeatable.
-f, --file <path>Run a script file and exit.
-c, --consistency <cl>one, quorum (default) or all.
-o, --format <fmt>pretty (default), table, or json (JSON Lines and nothing else).
--continue-on-errorKeep running a script after a statement fails.

Syntax

  • Arguments are JSON5: keys can be unquoted ({age: 31}), strings can use 'single quotes', and trailing commas are fine. Dotted keys need quotes: {"addr.city": "Leeds"}.
  • A statement can span lines. The shell keeps reading (...>) until brackets and quotes balance. Ctrl-C cancels a half-typed statement.
  • // starts a comment anywhere outside a string. # and -- start a comment at the beginning of a line. A trailing ; is optional.
  • Interactively, find() without .limit() shows the first 20 documents and says how many more matched. Scripts and -e return everything.

5. Working with documents

Inserting

// Any JSON object. _id is optional; a UUID is generated if it's missing.
db.users.insert({_id: "ann", name: "Ann Lee", age: 31, city: "Leeds",
                 tags: ["admin", "beta"], addr: {street: "1 Park Row", zip: "LS1"}})

db.users.insertMany([
  {_id: "bob", name: "Bob Hart", age: 25, city: "York",  tags: ["beta"], visits: 3},
  {_id: "cat", name: "Cat Moss", age: 42, city: "Leeds", addr: {zip: "LS6"}, vip: true},
  {_id: "dan", name: "Dan Webb", age: 17, city: "Hull",  visits: 12},
  {_id: "eve", name: "Eve Shaw", age: 58, city: "York",  tags: [], vip: false},
])

insert is an upsert, as in Cassandra: inserting an existing _id replaces that document.

Reading

db.users.get("ann")                  // by _id: reads only the replicas, the fastest lookup
db.users.findOne({city: "York"})     // first match
db.users.count()                     // 5
db.users.count({city: "Leeds"})      // 2

Filters

You wantFilter
equality{city: "Leeds"}
a nested field{"addr.zip": "LS1"}
an array containing a value{tags: "beta"}
an array element by position{"tags.0": "admin"}
a range{age: {$gte: 18, $lt: 40}}
any of / none of{city: {$in: ["York", "Hull"]}}, {city: {$nin: [...]}}
not equal{age: {$ne: 31}}
a field that exists / is missing{vip: {$exists: true}}, {addr: {$exists: false}}
null or missing{nickname: null}
an array of a given length{tags: {$size: 0}}
negation{age: {$not: {$gte: 18}}}
either / both / neither{$or: [...]}, {$and: [...]}, {$nor: [...]}
db.users.find({age: {$gte: 18, $lt: 40}})
_id  name      age  city   tags              addr                                 visits
---  --------  ---  -----  ----------------  -----------------------------------  ------
ann  Ann Lee   31   Leeds  ["admin","beta"]  {"street":"1 Park Row","zip":"LS1"}
bob  Bob Hart  25   York   ["beta"]                                               3
2 of 2 matching documents

db.users.find({$or: [{age: {$lt: 18}}, {vip: true}]})      // cat and dan
db.users.find({tags: "beta"})                              // ann and bob: matches inside arrays
db.users.find({addr: {$exists: false}})                    // bob, dan, eve
db.products.find({price: {$lt: 20}, stock: {$gt: 0}})      // conditions are ANDed
db.products.find({ratings: {$gte: 5}})                     // any array element >= 5

Comparisons only match values of the same type: {age: {$gt: "30"}} matches nothing when ages are numbers. Integers and floats compare as numbers (31 equals 31.0).

Sorting and paging

db.users.find({}).sort({age: -1})                                  // oldest first
db.users.find({}).sort({city: 1, age: -1})                         // by city, then oldest first
db.products.find({category: "kitchen"}).sort({price: 1}).limit(2)  // two cheapest
db.users.find({}).sort({_id: 1}).skip(2).limit(2)                  // page 2, page size 2

Without a sort, results come back ordered by _id. Missing fields sort first, like null. For deep paging, prefer keyset paging: sort on a unique field and ask for {field: {$gt: lastSeen}}, rather than a large skip.

Updating

db.users.update("bob", {$set: {city: "Leeds", "addr.zip": "LS2"}})  // set fields; creates addr
db.users.update("bob", {$inc: {visits: 1, age: 1}})                 // add to numbers
db.users.update("bob", {$push: {tags: "moved"}})                    // append to an array
db.users.update("bob", {$unset: {visits: ""}})                      // remove a field
db.products.updateMany({category: "living"}, {$set: {sale: true}})  // updated 2 documents
db.users.replace("eve", {name: "Eve Shaw", age: 59, city: "Hull"})  // replace the whole document

update reads the document, applies the operators, writes the result and returns the new document. Two concurrent updates to the same document resolve by last write wins. updateMany and deleteMany find the matching ids first, then change them one by one. They refuse to run if some nodes are unreachable, because the list of matches could be incomplete.

Deleting

db.users.delete("dan")                     // deleted dan
db.notes.deleteMany({pinned: true})        // deleted 1 document

A delete writes a tombstone. It's copied to the replicas like any other write and purged after --gc-grace-secs (10 days by default).

Indexes and explain()

Without an index, every node scans the whole collection. explain() shows what each node did:

db.people.find({city: "Ely", age: {$gt: 85}}).explain()
node   plan       examined  matched
node1  full scan  2000      27
node2  full scan  2000      27
node3  full scan  2000      27

db.people.createIndex("age")     // defined cluster-wide, built in the background on every node
db.people.indexes()
field  created_ts        state
age    1794680667212413  ready

db.people.find({city: "Ely", age: {$gt: 85}}).explain()
node   plan       examined  matched
node1  index age  158       27
node2  index age  158       27
node3  index age  158       27

Indexes serve equality, $in, and ranges ($gt $gte $lt $lte, on numbers or strings). If several conditions are indexed, the planner prefers equality, then $in, then ranges. Index a field that holds arrays and each element is indexed. Index nested fields with a dotted path: createIndex("addr.city"). Queries that use $or, $ne, $exists or null scan instead.

With a node down

cassango 127.0.0.1:7001> db.users.get("ann").consistency("all")
error: 503 unavailable: 3 replicas required but only 2 alive

cassango 127.0.0.1:7001> db.users.find({city: "Leeds"})
...
3 of 3 matching documents — PARTIAL: some nodes were unreachable

PARTIAL means find couldn't ask every node. With RF 3 and one node down, every document is still on two live nodes, so in practice nothing is missing.

6. Scripting and automation

Script files hold the same statements you'd type in the shell:

// seed.cassango
db.users.insertMany([
  {_id: "ann", name: "Ann", city: "Leeds"},
  {_id: "bob", name: "Bob", city: "York"},
])
db.users.createIndex("city")
db.users.count()
cassango-cli -f seed.cassango                      # stops at the first error, exit code 1
cassango-cli -f seed.cassango --continue-on-error  # keep going; exit code 1 if anything failed

# -o json prints JSON Lines and nothing else, so it pipes cleanly
cassango-cli -o json -e 'db.people.find({age: {$gte: 89}}).limit(3)' | jq -c '{name, age}'
cassango-cli -o json -e 'db.users.find({})' > users.jsonl        # export
jq -c 'del(._id)' users.jsonl | sed 's/.*/db.users_copy.insert(&)/' | cassango-cli   # import

cassango-cli <<'EOF'
db.orders.insert({_id: "o1", user: "ann", total: 42.5})
db.orders.find({total: {$gt: 40}})
EOF

Exit codes: 0 success, 1 a statement failed (bad syntax, server error, cluster unreachable), 2 bad command-line flags.

7. The Rust driver: cassango-client

[dependencies]
cassango-client = { path = "../cassango/client" }
serde = { version = "1", features = ["derive"] }
serde_json = "1"
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }

The driver is async and runs on tokio through reqwest. It doesn't depend on any server code.

Connecting

use cassango_client::{Client, Consistency};
use std::time::Duration;

let client = Client::new("127.0.0.1:7001")?;                     // one host, defaults

let client = Client::builder()
    .hosts(["10.0.0.5:7001", "10.0.0.6:7001", "10.0.0.7:7001"])  // tried in order if one is down
    .consistency(Consistency::Quorum)                          // default for reads and writes
    .timeout(Duration::from_secs(10))                          // per request (default 30 s)
    .connect_timeout(Duration::from_secs(1))                   // before trying the next host
    .build()?;

client.refresh_hosts().await?;   // replace the list with every UP node the cluster reports

Client is cheap to clone and safe to share across tasks. Clones share connections.

A complete program

use cassango_client::{Client, Filter, Order, Update};
use serde::{Deserialize, Serialize};
use serde_json::json;

#[derive(Debug, Serialize, Deserialize)]
struct User {
    #[serde(rename = "_id")]   // map a field to the document id
    id: String,
    name: String,
    age: u32,
    city: String,
}

#[tokio::main]
async fn main() -> cassango_client::Result<()> {
    let client = Client::builder().hosts(["127.0.0.1:7001", "127.0.0.1:7002"]).build()?;
    let users = client.collection::<User>("users");

    let ann = User { id: "ann".into(), name: "Ann".into(), age: 31, city: "Leeds".into() };
    users.insert(&ann).await?;
    let found: Option<User> = users.get("ann").await?;

    let leeds = users
        .find(Filter::new().eq("city", "Leeds").gte("age", 18))   // or json!({...})
        .sort_by("age", Order::Desc)
        .limit(10)
        .await?;
    println!("{} of {} matches", leeds.docs.len(), leeds.matched);

    users.update("ann", Update::new().inc("age", 1)).await?;
    let adults = users.count(json!({"age": {"$gte": 18}})).await?;
    users.delete("ann").await?;
    Ok(())
}

Filters and updates

let f = Filter::new()
    .is_in("city", ["York", "Hull"])
    .exists("email", true)
    .or([Filter::new().lt("age", 18), Filter::new().eq("vip", true)]);
let n = users.count(f).await?;
// Filter: eq ne gt gte lt lte is_in not_in exists size or nor
// Operators on one field merge: .gte("age", 18).lt("age", 65) → {"age": {"$gte": 18, "$lt": 65}}

let bob = users.update("bob", Update::new()
        .set("addr.city", "Leeds")   // dotted paths create nested objects
        .inc("visits", 1)
        .push("tags", "moved")
        .unset("nickname"))
    .await?;                         // Some(updated) or None

users.create_index("age").await?;
users.wait_for_index("age", Duration::from_secs(30)).await?;
let r = users.find(Filter::new().gt("age", 30)).explain().await?;

Errors

Every method returns cassango_client::Result<T>. err.is_retryable() is true for Unavailable, Timeout, Transport and Partial.

The driver turns on serde_json's preserve_order feature, so json!({"a": 1, "b": -1}) sort specs keep the order you wrote them in. Cargo features are shared across a build, so serde_json::Map keeps insertion order in your whole project too.

9. Running a cluster

Local processes: scripts/cluster.sh

scripts/cluster.sh start 3          # node1..node3 on ports 7001..7003 (data/ and logs/)
scripts/cluster.sh status           # cluster view from node1 (JSON)
scripts/cluster.sh kill 2           # hard-kill node2
scripts/cluster.sh restart 2        # start it again
scripts/cluster.sh join 4           # add node4; it streams its share of the data
scripts/cluster.sh cleanup          # drop data the old owners gave away after a join
scripts/cluster.sh decommission 2   # node2 hands its data to the others and stops
scripts/cluster.sh removenode node3 # node3 is dead for good: copy its data from the survivors
scripts/cluster.sh repair           # anti-entropy repair on every node
scripts/cluster.sh stop             # stop everything (memtables are flushed)
scripts/cluster.sh clean            # stop and delete data/ and logs/

Environment variables: RF, MEMTABLE_MB, RING_DELAY_MS, EXTRA_ARGS.

Docker: six nodes with docker compose

docker build -t cassango:latest .      # multi-stage build: rust:slim → debian:bookworm-slim
docker compose up -d                   # RF 3, repair every 24 h (--repair-interval-secs 86400)
docker compose ps                      # all six should be "healthy"
docker compose stop cassango3          # simulate a failure; writes keep working at quorum
docker compose down                    # stop and remove the containers; the volumes are kept
docker compose down -v                 # ... and delete the data

Walkthrough: failure, recovery, growth

# 1. A node fails. Writes keep working at quorum and are queued for it.
scripts/cluster.sh kill 2
cassango-cli -e 'db.users.insert({_id: "zed", name: "Zed"})'
cassango-cli -e 'show cluster'       # a few seconds later: node2 DOWN, "pending hints 1"

# 2. It comes back. The queued writes are delivered within a few seconds.
scripts/cluster.sh restart 2
cassango-cli -e 'show cluster'       # node2 UP, "pending hints 0"

# 3. Make sure all replicas agree, e.g. after a long outage.
scripts/cluster.sh repair            # node1: ranges=16 in_sync=16 repaired=0 ...

# 4. Grow the cluster. node4 starts as JOINING, streams its ranges, then turns NORMAL.
scripts/cluster.sh join 4
scripts/cluster.sh cleanup           # free the space the old owners no longer need

# 5. Shrink it again.
scripts/cluster.sh decommission 4    # streams node4's data away, marks it LEFT, stops it

Operational rules of thumb. Run a repair on every node more often than --gc-grace-secs, otherwise a deleted document can come back. Change one node at a time: decommission, removenode and cleanup refuse to run while another node is joining or leaving. Stop nodes with SIGINT (Ctrl-C, or docker compose stop, which sends SIGINT) so they flush their memtables. After a crash, the commit log is replayed on startup.
